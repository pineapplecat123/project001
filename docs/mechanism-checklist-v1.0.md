## 一、战斗核心循环

| 项 | 规则 |
|---|---|
| 弹药袋 | 等同卡牌构筑游戏里的**牌库**。里面装了玩家拥有的所有子弹。无上限，同名子弹无上限。 |
| 弹夹 | 等同卡牌构筑游戏里的**手牌**。6 个子弹仓，是一个**有顺序的结算队列**。 |
| 每回合开始 | 从弹药袋随机抽 6 发，按顺序装满弹夹。 |
| 弹药袋抽空时 | 当回合能抽几发装几发（例如只剩 3 发就只装 3 发），**下回合**把弃牌堆 + 已消耗子弹全部洗混放回弹药袋，再抽。 |
| 重roll（建议改名以防歧义） | 旋转整个弹夹，重新选择一个起始击发子弹（即重新选择队列的头尾）。因为是循环队列，**不改变队列的连续顺序**。不消耗弹药，免费无限制。**代价是消耗一个回合**。 |
| 卸除 | 将弹夹内子弹全部卸除丢弃，进入**弃牌堆**。不是永久移除；弹药袋抽空洗回时，弃牌堆一并回到弹药袋。免费无限制。**代价是消耗一个回合**。 |
| 射击 | 按当前弹夹顺序（即结算队列）**立即依次击发所有子弹**，并结算互相效果。执行后回合结束。 |
| 玩家每回合操作 | 装填完成后，在 射击 / 重roll / 卸除 中**三选一**，执行后立即结束玩家回合，进入怪物回合。 |
| 回合轮换 | 玩家回合 → 怪物回合 → 玩家回合 → …… |
| 战斗回合上限 | 无。因为怪物会逐步逼近，最终不是玩家死就是怪物全灭。 |

### 文档中的结算队列示例（保留原文，供 bot 理解“队列内互相影响”）

**示例一（状态连锁）**：待击发顺序为 4 发油弹、1 发高爆弹、1 发水弹。先射击 4 发油弹 → 给怪物叠加 4 层油；第 5 发高爆弹击中 → 爆炸同时点燃 4 层油，怪物进入 4 层燃烧；第 6 发水弹击中 → 将燃烧浇灭，从 4 层燃烧变为 3 层燃烧。

**示例二（同名子弹按出现次数改变伤害）**：一种叫 A 子弹的效果是“在弹夹中出现的次数决定伤害”。它被装在第 1、3、5 仓，其余三仓是固定 3 伤害的常规子弹。A 子弹第 1 次出现伤害 2，第 2 次出现伤害 3，第 3 次出现伤害 4。击发后伤害队列为：2、3、3、3、4、3（共开 6 枪）。

> 以上例子仅用于说明“结算队列”和“队列内互相影响”的机制，并非游戏内实际存在的子弹种类。实际子弹种类见子弹种类表。

### 战斗操作流程（原文细化）

1. 点击 **LOAD**：随机抽取装满弹夹数量的子弹，按顺序填装进弹夹（不称“左轮弹夹”，是为将来其他弹夹和枪械留余地）。
2. 装填时有**视窗实时预览**弹夹内子弹填装情况。
3. 装填完成后选择 **FIRE / ROLL / UNLOAD** 之一，执行效果。
4. 进入怪物回合。
5. 循环。

## 二、平台、格子与怪物

| 项 | 规则 |
|---|---|
| 格子总数 | 10 格（暂定）。格子**需要可见**。 |
| 玩家位置 | 固定在最左侧格子。 |
| 怪物出生 | 单个怪物出生在最右格；多个怪物时，一只在最右格，其余在其右侧（画面外）排队。 |
| 怪物移动 | 每回合默认向玩家移动 1 格（有特殊设定的怪除外）。 |
| 怪物攻击 | 移动后若与玩家**相邻**则攻击一次，之后留在该格，**不会与玩家重叠**。常规情况下怪物只能攻击邻侧。 |
| 怪物阻挡 | 怪物之间互相阻挡，**每个格子最多一只怪物**。 |
| 怪物意图 | **不显示**下一步意图。 |
| 怪物行为模式 | 靠近、攻击。 |
| 怪物关键词系统 | 有。例：生物=常规属性、被击中会流血；骷髅=被击中不会流血；石头=无视小于 3 的伤害、难以被击穿。以上仅为举例，具体见怪物设定。 |
| 多怪物关卡 | 若干怪物从右侧向玩家靠近，初始只显示最前一只，其余在画面外。每回合结束时怪物集体向玩家靠近。 |
| 穿透/范围子弹 | 有些子弹拥有穿透或大范围攻击效果，具体见子弹种类表。 |
| 战斗规模 | 普通战斗约 3–6 回合过关；敌人越多回合数越多。 |
| 精英 vs Boss | 精英=数值提升过的小怪（血更多、攻击更高、范围更广、速度更快等）；Boss=有独一无二的特性和效果（例：往玩家弹夹或弹药袋里塞无效子弹）。 |

## 三、伤害与胜负

| 项 | 规则 |
|---|---|
| 伤害类型（灰盒） | 只需先做**基础数值系统**：常规伤害=基础数字。暴击率、状态异常等灰盒先不做（但 Q4b 要求 3 种子弹含最小连锁演示，故需搭轻量状态/联动机制）。 |
| 玩家失败 | 血量归零 = **整局游戏结束**，不只是当前小关卡失败。 |
| 胜利 | 当前关卡所有怪物血量归零，玩家通过该关卡。 |

## 四、构筑系统

| 项 | 规则 |
|---|---|
| 构筑对象 | 弹药袋里的子弹。具体种类见子弹种类表。 |
| 上限 | 弹药袋无上限，同名子弹无上限。 |
| 稀有度 | 有稀有度设定；但**灰盒阶段不分稀有度**，所有子弹放在一个随机池，不做权重区分。 |
| 获取途径 | 战斗奖励、商店购买、特殊事件。 |
| 移除 | **仅商店**可花钱移除子弹。费用**单店累计递增**：第一次 10 金币，第二次 15 金币，以此类推；离店重置。 |
| 升级 | 子弹目前**无法升级**，无升级系统。不排除未来加入。升级属于战斗外系统。 |
| 附魔/二合一 | 未来也许可以，灰盒不做。 |
| 流派设计初衷 | **不做严格明确流派**，旨在让玩家自己研究出不同流派可能性；具体做法需探索。 |
| 奖励三选一 | 随机三个，玩家选一个。商店库存随机。有重随机制。 |
| 构筑调整时机 | 仅在特殊节点：战斗后奖励、商店。其他场合只能**查看**构筑，不能变更。 |
| 构筑成本 | 构筑绑定经济系统，有成本（商店花钱、打怪获得）。 |
| 构筑界面灰盒最低要求 | 战斗外可打开子弹袋查看所有子弹（含子弹信息）；战斗后和商店可获得子弹加入；商店内可删除子弹。 |

### 构筑与战斗的耦合示例（原文保留）

构筑时选择多个**闪电子弹**放入弹药袋。闪电子弹效果：多个闪电子弹在弹夹排列中**互相挨着**时大大增强伤害和效果；单个只能打单体伤害，多个挨着能打范围伤害。构筑时只拿闪电子弹 → 提高战斗中抽到闪电子弹的概率 → 更容易打出连锁效果。

## 九、灰盒范围与内容规模

### 第一版必须跑通的机制
地图节点选择、进入战斗、战斗后奖励结算、商店购买、基本构筑系统、基本战斗系统。

### 第一版内容量
1 个基础敌人、若干种子弹（见子弹表）、缩小版一层地图、1 个 Boss。

### 灰盒阶段战斗最小集
1 个玩家、1 种常规敌人、**3 种子弹**、战斗后奖励选择、胜负判定。

### Q4b：3 种子弹必须包含一组最小连锁演示
灰盒 3 种子弹中**至少包含一组最小连锁演示**，验证“连锁”爽点。形式不限，例如：
- 子弹 A 给敌人挂状态，子弹 B 消耗该状态造成额外伤害；
- 或子弹 A + 子弹 B 相邻时触发额外效果。

→ 因此 bot 第一版需实现**轻量状态/联动机制**，不能只做独立伤害。

### 验收方式
逐步验收，不要求一步到位；每次有阶段性成果（如实现一个 feature）时验收一次。验收包含 bot 递交录屏/GIF + 你亲自试玩网页部署版。

### 后续内容
灰盒后的内容由你和 bot 聊天逐步增加。

## 十、数据管线

| 项 | 规则 |
|---|---|
| 设计源格式 | **Excel 表格**。 |
| 交接方式 | 在**聊天里直接粘贴**给 bot。 |
| bot 的职责 | bot 读表后，**自己生成一个文档进行管理**，放入 GitHub 某个路径；并**自行生成运行时数据文件**（格式由 bot 决定，如 JSON / `.tres`），游戏读该文件。 |
| 表格定位 | 表格**只是设计源**，不是运行时直接读取的文件。 |
| 列结构 | 由**你自己构思编写**。bot 按你给的列写解析，**不先提草案**。 |
| 衔接规则 | 你贴表 → bot 读表 → bot 设计运行时数据结构并生成文件 → 若某列**无法映射或语义不明**，bot **必须停下询问**（十分重要级），**不得自行猜测或丢弃列**。 |
| 覆盖范围 | 子弹、敌人、事件的数据均用表格递交。 |

## 十一、表现与 UI

| 项 | 规则 |
|---|---|
| 美术风格 | 暂定**粗粝像素风**；之后提供美术资源。 |
| 灰盒占位符 | 色块/几何图形即可，**bot 自定风格**。 |
| UI 早期原则 | 尽量展示多信息，便于测试，之后再 polish。 |
| 音效音乐 | **先不加**，以后再逐步添加。 |
| 游戏内文本语言 | 中文；保留未来添加英文的可能性。实现方式（是否现在抽语言文件）由 bot 选更优方案。 |
| 弹夹 UI | **环形转轮**，上面 6 个圆形代表 6 个子弹仓；其中**一个红色圆形叠加在最上方的子弹仓**，代表这是第一个击发；转轮上需**标上旋转方向和击发顺序**。 |
| 格子显示 | **需要可见**。 |
| 触屏兼容 | 灰盒阶段**按钮可点即可**。 |
| 分辨率适配 | Web 端需考虑分辨率适配。 |
| 主菜单 | 包含**开始游戏、退出游戏**；未来加入存档系统；需有**更新日志按钮**。 |
| 版本号展示 | 在**游戏最下方**展示；**主菜单和游戏内都显示**。 |
| 更新日志 | 主菜单按钮点开可查看。 |
| 调试面板 | 用 **UI 按钮呼出**；功能：随意在子弹袋加/减子弹、一键杀死敌人、添加金币等。 |
| 叙事 | 目前以玩法为主，**暂无文字包装**；确保玩法跑通为重点。 |

## 十二、技术与工程约束

| 项 | 规则 |
|---|---|
| 引擎 | Godot **4.7.2 stable**，锁定，非你主动要求不升级。 |
| 语言 | **GDScript**（Web 导出强制约束）。 |

## 十四、重要度分级提醒（摘自 Harness）

本清单中标注“十分重要级”的事项，bot 必须停下等审批。涉及本清单的包括：

- 表格某列无法映射或语义不明 → 停下询问；
- 机制歧义且无合理默认假设 → 停下询问；
- 影响核心机制、数据结构、存档格式的改动 → 停下审批；
- 同一 bug 超过 10 次尝试 → 停下等你选择回滚或跳过。

其余按 Harness 的“一般重要=告知”“不重要=自行决断简短告知”执行。
